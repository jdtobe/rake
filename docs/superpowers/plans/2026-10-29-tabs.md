# Independent Terminal Tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver independent terminal tabs with safe close/quit, local-directory inheritance, optional layout restoration and independent UI appearance.

**Architecture:** Rust owns ordered tab metadata and PTY resources keyed by stable IDs. One WKWebView holds one xterm per tab; a bounded, acknowledged output bridge prevents background output from overwhelming the UI. Pure models decide actions; small macOS adapters inspect processes and show dialogs, while main.rs only routes events.

**Tech Stack:** Existing Rust/tao/wry/portable-pty/xterm.js; macOS libproc through `libc`; AppKit through objc2. Node's test runner and Playwright WebKit for real browser-side tests (development dependencies only).

**Spec:** `docs/superpowers/specs/2026-10-29-tabs-design.md` (approved).

## Global Constraints

- This is a macOS implementation; do not claim support for other platforms.
- Tab bar at the bottom by default; top placement configurable. Keep it visible with one tab.
- Settings initially live in the existing TOML config and apply on restart.
- Never reconnect SSH. No running commands, scrollback or command history are restored by Rake.
- System (default), Light and Dark affect Rake controls, not terminal colours or font.
- All in-app close/quit controls share confirmation policy; uncertainty prompts rather than silently killing work.
- IDs are independent of indices; reordering is wanted follow-up, not part of this milestone.
- No general Settings window, profiles, splits or release publication.
- Preserve existing single-instance behaviour, display/Spaces placement, PTY persistence, clipboard and completed-shell behaviour.
- Every task uses red → green → refactor, then `cargo test`, clippy and fmt before its logical commit. Do not merge partial foundations with unused public APIs; exercise each new interface in its tests and integrate at the indicated task.

## Review Focus

- Delayed callbacks after removal or selection change must not write, paste or rename another tab (Tasks 1, 4, 5, 9).
- Heavy inactive output must remain bounded without starving input; closing must unblock a waiting worker (Tasks 4, 5, 9).
- PID reuse, denied inspection, stopped/background jobs and shell exit must never be mistaken for an idle shell or an unrelated kill target (Task 3).
- Missing directories, non-UTF-8 paths and interrupted layout writes must preserve usable startup and avoid corrupting saved state (Tasks 2, 7).
- Reentrant native menus/dialogs and repeat key events must not cause duplicate tab creation or bypass cancellation (Tasks 6, 8, 9).

## File boundaries

- `src/tabs.rs`: pure ordered metadata, naming, lifecycle and selection; `TabId` is shared by all session protocols.
- `src/config.rs`: five enums and defaults. `src/tab_layout.rs`: versioned persistence and startup resolution.
- `src/process.rs`: portable observation types and pure busy/identity policy; `src/process/macos.rs`: libproc and safe signalling boundary.
- `src/pty.rs`: cwd-aware spawn, retain shell identity and expose job observation/termination.
- `src/session_output.rs`: bounded queues/credits/fair scheduling. `src/sessions.rs`: PTY ownership and routing.
- `src/terminal_protocol.rs`: validated tagged IPC and typed UI deliveries. `src/terminal_view.rs`: webview only, no tab policy.
- `assets/terminal/tabs.js`, `tabs.css`: tab DOM/actions; `rake.js`: xterm lifecycle; `index.html`: workspace layout.
- `src/workspace.rs`: command coordinator, connects tab/session/layout/close policies; keep main.rs thin.
- `src/close_policy.rs`: pure pending-decision model. `src/app_ui.rs`: native menus, confirmation dialogs and native appearance.
- `tests/terminal/`: Playwright tests exercising the bundled document, not source-text matching.
- `package.json`, `package-lock.json`, `playwright.config.js`: development-only browser test tooling.
- `src/lib.rs`, `src/dropdown.rs`, `src/main.rs`: module registration and integration.
- `README.md`, `docs/roadmap.md`, new ADR: truthful shipped behaviour and reordering follow-up.

## Task 4: Bounded per-session transport and tagged IPC

**Files:** Create `src/session_output.rs`; modify `src/terminal_protocol.rs`, `src/terminal_view.rs`, `src/lib.rs`.

**Interfaces:** `SessionOutput::new()`, `register(id)`, `send(id, event: TerminalEvent) -> Result<(), Closed>`, `take_batch() -> Vec<SessionDelivery>`, `ack(id, sequence: u32)`, `close(id)`. `SessionDelivery { id: TabId, sequence: u32, event: TerminalDelivery }`. Sender handles are cloneable and thread-safe; UI owns the drain side. One coalesced wake notification schedules draining, not a tao event per output chunk. Sequence numbers are per ID and cannot wrap into a pending delivery.

IPC variants: global `Ready`, `NewTab`, `SelectTab{id}`, `SelectNumber{number}`, `CycleTab{backwards}`, `CloseTab{id}`, `RenameTab{id,text}`; tagged `Input{id,data}`, `Resize{id,cols,rows}`, `Copy{id,data}`, `Paste{id}`, `Title{id,text}`, `OutputAck{id,sequence}`. Preserve existing strict field/type validation. UI deliveries include `CreateTab`, `RemoveTab`, `SelectTab`, `TabMetadata`, `Notice`, and tagged terminal output/exit/paste; serialize payloads with serde, never concatenate unescaped title/path strings into JavaScript.

- [ ] Write tests `tabs_keep_independent_order_and_exit_after_output`, `removed_tab_wakes_blocked_sender`, `one_noisy_tab_cannot_starve_another`, `invalid_or_duplicate_ack_does_not_release_credit`, `late_removed_id_events_are_ignored`, `wire_rejects_missing_or_invalid_id_and_extra_fields`.
- [ ] Pin limits in tests: 256 KiB outstanding output bytes per tab across queued and in-flight data, chunks at most 8192 bytes, one at-most-64-KiB drain per tab per pump in round-robin order. Acks release credit only after xterm write callbacks. Exit/failure follows output; closing discards queues and wakes blocked writers. A paused browser must block the producer, not grow another queue. Document readiness must precede creation and session output.
- [ ] Run targeted tests to observe red; implement a Mutex/Condvar credit ledger with cancellation and bounded events, replacing—not layering over—the old unbounded bridge. Preserve delivery on evaluate_script failure; do not release credit until acknowledgement. Lifecycle deliveries need no output credit but cannot overtake bytes. Unsent batches stay bounded by the same ledger.
- [ ] Run all Rust tests/lints/fmt; commit `feat: terminal bridge - bound and route output by session`.
