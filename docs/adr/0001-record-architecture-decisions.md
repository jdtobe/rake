# 1. Record architecture decisions

Date: 2026-10-19 · Status: Accepted

## Context
The project's first attempt left behind many stub files and documents describing code that did not exist. The reasons behind choices were lost.

## Decision
Record each significant decision as a short ADR in `docs/adr/`, numbered in order, with context, decision and consequences. Do not edit accepted records. Supersede them with a new one.

## Consequences
Small overhead per decision. In return, future contributors, human or AI, can see why the code is shaped the way it is.
